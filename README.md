# 나비글쓰기 · 1–15단계

임의 모양 영역(도넛형 포함)에 리치 텍스트와 블록 이미지를 흘려 넣는 자체 레이아웃 엔진(1단계), 그 결과 위에서 직접 편집하는 편집기(2단계), 글자 꾸밈 명령·전역 되돌리기·복사/붙여넣기(3단계), PNG·JPG·WebP·PDF 출력(4단계), Electron 설치형 앱(5단계), 편집기 화면 1차 — 요소 만들기·선택·이동·리사이즈·회전·스냅·그룹·정렬(6단계), 레이어·속성 패널·스와치·스포이트(7단계), 여러 장·프로젝트 저장·자동 저장과 복구·에셋 라이브러리(8단계)입니다.
vanilla JS ES 모듈로 작성했고 번들러가 없습니다. ProseMirror는 `vendor/`에 포함되어 있으며 import map으로 불러옵니다. 오프라인에서도 동작하고 Electron에서도 그대로 쓸 수 있습니다.

## 실행

**웹판** — ES 모듈이라 `file://`로는 열리지 않습니다. 로컬 서버가 필요합니다.

```
cd proto
python -m http.server 8000     # 또는 npx serve
# 크롬에서 http://localhost:8000          → 편집기(index.html)
#        http://localhost:8000/demo.html → 1–4단계 엔진 데모(도넛·이미지 외곽선 프레임 4개)
```

**Windows에서 더블클릭으로** — 명령어를 치지 않아도 됩니다(Node.js 22 이상만 먼저 설치: nodejs.org의 LTS).

- `build-installer.bat`(설치 파일 만들기): 필요한 도구를 받고(처음 한 번, 몇 분) 설치 파일을 만든 뒤 `dist` 폴더를 열어 줍니다. 결과 `dist\Nabitext-버전-win-x64.exe`
- `run-app.bat`(바로 실행): 설치하지 않고 앱을 바로 켭니다(고친 것 확인용)
- Node.js가 없으면 설치 페이지를 열어 주고 멈춥니다. 도중에 멈추면 창의 마지막 몇 줄을 보내 주십시오.
- zip을 **먼저 모두 풀고**(오른쪽 클릭 → 압축 풀기) 푼 폴더 안에서 더블클릭하십시오. zip 안에서 바로 누르면 `scripts` 폴더를 못 찾는다는 안내가 나옵니다.
- 구조: `.bat`은 영문만 들어 있는 짧은 실행기이고, 실제 일은 `scripts/build-installer.ps1`·`scripts/run-app.ps1`(PowerShell)이 합니다. 창은 성공·실패와 관계없이 마지막에 "아무 키나 누르십시오"에서 멈춥니다.

**설치형(Electron)** — Node.js 22 이상이 필요합니다.

```
cd proto
npm install          # Electron과 electron-builder를 받습니다(처음 한 번)
npm start            # 개발 실행: 웹판과 같은 파일을 그대로 불러옵니다
npm run dist:win     # Windows 설치 파일 → dist/Nabitext-0.6.0-win-x64.exe (Windows에서 실행)
npm run dist:mac     # macOS 디스크 이미지 → dist/*.dmg (Mac에서만 가능)
npm run dist:linux   # Linux AppImage
npm run build:web    # 웹판 배포 폴더 → dist/web (Cloudflare Pages 출력 폴더로 지정)
```

Mac이 없어도 `.github/workflows/build.yml`로 세 운영체제 설치 파일을 GitHub에서 만들 수 있습니다(저장소에 올린 뒤 Actions 탭 → build → Run workflow → 끝나면 Artifacts에서 내려받기).

**엔진 데모(demo.html)**: 네 프레임 모두 클릭해서 바로 편집할 수 있습니다. 상단 컨트롤로 여백, 외곽 다듬기, 글자 크기를 조절하면 즉시 다시 배치됩니다. "영역·줄 표시"를 켜면 마스크(파랑)와 줄 구간(빨강)이 표시되고, "검증 실행"을 누르면 1단계 검증 항목을 현재 문서로 다시 계산합니다.

## 편집 동작

| 입력 | 동작 |
|---|---|
| 클릭 / 드래그 / Shift+클릭 | 커서 배치, 범위 선택, 선택 확장 |
| 더블클릭 / 트리플클릭 | 단어 선택 / 문단 선택 |
| ← → | 글자(grapheme) 단위 이동. 이모지 조합 문자도 한 번에 넘어감. Ctrl을 누르면 단어 단위 |
| ↑ ↓ | 목표 x를 유지하며 위/아래 띠로 이동. 한 띠에 구간이 여러 개면 목표 x에 가장 가까운 구간 |
| Home / End | 현재 **구간** 처음/끝(도넛에서는 왼쪽 구간과 오른쪽 구간이 각각 한 줄). Ctrl을 누르면 문서 처음/끝 |
| Backspace / Delete | 음절(grapheme) 단위 삭제. 문단 경계에서는 문단 합치기. Ctrl을 누르면 단어 단위 |
| Enter / Shift+Enter | 문단 나누기 / 강제 줄바꿈 |
| Ctrl+A | 전체 선택 |
| 이미지 클릭 | 이미지 노드 선택(테두리 표시). Delete나 Backspace로 삭제 |
| 한글 입력 | 조합 중인 글자는 문서에 넣지 않고 화면에만 밑줄과 함께 표시. 확정 시 1회 삽입. 입력창이 커서를 따라다녀 IME 후보창이 커서 옆에 뜸 |

## 단축키 (3단계)

기본 배치는 `src/keymap.js`의 `DEFAULT_KEYMAP`. Mod는 macOS에서 Cmd, 그 외 Ctrl입니다.

| 키 | 명령 |
|---|---|
| Mod+Z / Mod+Shift+Z / Mod+Y | 되돌리기 / 다시 실행 / 다시 실행 |
| Mod+B / Mod+I / Mod+U | 굵게 / 기울임 / 밑줄 |
| Mod+Shift+X | 취소선 |
| Mod+Shift+> / Mod+Shift+< | 글자 크기 한 단계 크게 / 작게 (`SIZE_STEPS`: 8 … 200) |
| Mod+\ | 꾸밈 전부 해제 |
| Mod+A | 전체 선택 |
| Mod+C / Mod+X / Mod+V | 복사 / 잘라내기 / 붙여넣기 |
| Mod+Shift+V | 서식 없이 붙여넣기 |

- **재지정:** `createKeymap({ 'Mod-Shift-s': 'strike', 'Mod-Shift-x': null })` — 값이 `null`이면 해제. 명령 이름은 `editor.commands`의 키(`undo`, `redo`, `bold`, `italic`, `underline`, `strike`, `overline`, `sizeUp`, `sizeDown`, `clearMarks`, `selectAll`)
- **한글 자판 상태:** 한글 입력 상태에서는 Ctrl+B가 `e.key = 'ㅠ'`로 들어올 수 있습니다. 먼저 `e.key`로 찾고, 없으면 물리 키(`e.code`)로 다시 찾습니다. Shift로 바뀐 문자(`>`, `<`)도 같은 방식으로 처리합니다.
- **도구 막대·속성 패널용 API:** `editor.toggleMark(name, attrs)`, `editor.setMark(name, attrs)`, `editor.removeMark(name)`, `editor.markState(name)` → `{ state: 'all' | 'some' | 'none', values: [attrs…] }`. 버튼은 `mousedown`에서 `preventDefault()`해야 편집기 포커스와 한글 조합이 유지됩니다(데모의 되돌리기 버튼 참고).

## 마크 명령 규칙

- **켜고 끄는 마크**(굵게·기울임·밑줄·취소선·윗줄): 선택 전체에 이미 있으면 끄고, 일부에만 있거나 없으면 전체에 켭니다(워드·구글 문서 규칙). 공백도 선택된 그대로 적용합니다.
- **값 마크**(굵기·색·형광펜·크기·글꼴·자간·행간·외곽선·그림자·그라디언트·선 모양): 같은 종류는 새 값으로 바뀝니다.
- **굵게와 굵기(weight)는 한 글자에 하나만** 둡니다(스키마 `excludes`). 나중에 적용한 쪽이 남습니다.
- **선택이 비어 있으면** 다음에 입력할 글자의 꾸밈을 바꿉니다(한글 조합 중 미리보기에도 반영).
- **크기 단계:** 글자마다 현재 크기(크기 마크, 없으면 문단 스타일 → 프레임 스타일 → 기본값)에서 다음 단계로. 크기가 섞인 범위도 각자 한 단계씩.

## 되돌리기

- **전역 스택 하나:** 프레임이 여러 개여도 스택은 하나입니다(`History`). 다른 프레임의 변경을 되돌리면 그 프레임으로 포커스가 옮겨 갑니다. 항목은 `{ undo(), redo() }` 인터페이스라 이후 요소 이동·리사이즈·속성 변경도 같은 스택에 넣습니다. ProseMirror `history` 플러그인은 편집기마다 따로 스택을 가지므로 쓰지 않았습니다.
- **텍스트 항목:** 트랜잭션의 step과 뒤집은 step을 저장합니다. 편집기 문서는 모두 이 스택을 거쳐서만 바뀌므로 순서대로 적용하면 항상 맞습니다(적용 실패 시 예외).
- **연속 입력 묶기:** 같은 프레임, 같은 종류(입력 / 삭제), 커서가 직전 결과 위치 그대로, 간격 1초(`groupDelay`) 이내면 한 단위. 글자 입력·한글 확정·Enter·Shift+Enter가 '입력', 한 글자/단어 Backspace·Delete가 '삭제'입니다. 선택 위에 입력하면 선택 삭제와 입력이 한 단위라, 되돌리면 원문과 선택이 함께 돌아옵니다. 마크 적용, 붙여넣기, 잘라내기, 선택 범위 삭제는 각각 단독 단위입니다.
- **조합 중 되돌리기**(버튼 등): 조합 글자를 먼저 확정한 뒤 되돌리므로 조합 중이던 글자만 취소됩니다.
- **메뉴의 되돌리기**(Electron 편집 메뉴 → `beforeinput: historyUndo`)도 입력창 자체 기록이 아니라 전역 스택으로 보냅니다. 편집기 밖에 포커스가 있을 때의 Ctrl+Z는 데모 `main.js`의 문서 단위 리스너가 처리합니다.

## 복사 / 붙여넣기

- **복사:** `text/html`과 `text/plain`을 함께 씁니다. HTML은 인라인 CSS라 워드·구글 문서 같은 외부 프로그램에서도 모양이 유지되고, 최상위 요소에 슬라이스 JSON(`data-le-slice`)을 넣어 이 프로그램끼리는 마크·문단 속성이 손실 없이 옮겨집니다. 선택이 비어 있으면 클립보드를 건드리지 않습니다.
- **붙여넣기 우선순위:** 이 프로그램의 슬라이스 → 이미지 파일 → 외부 HTML → 텍스트.
- **외부 HTML:** 기본은 굵게·굵기·기울임·밑줄·취소선·윗줄만 살리고 색·크기·글꼴 등은 버려 프레임 스타일을 따릅니다(웹페이지·구글 문서는 모든 글자에 색과 크기를 박아 넣기 때문). `externalMarks: 'all'`이면 전부 살립니다. `p`, `div`, `h1–6`, `li`, `br`은 문단 구조로 옮기고, 구글 문서의 `<b style="font-weight:normal">` 감싸기는 굵게로 보지 않습니다.
- **텍스트:** 줄바꿈마다 문단. 글자는 커서 위치의 꾸밈을, 새 문단은 현재 문단 속성(정렬 등)을 이어받습니다.
- **이미지 파일:** 문단 사이 이미지로 삽입, 기본 폭은 원본 폭과 프레임 폭의 절반 중 작은 값.
- **이미지를 불러오지 못하면**(외부 HTML의 끊긴 주소 등) 그 이미지만 빼고 붙여넣습니다. 영역 배치에 원본 크기가 필요하기 때문입니다.

**조합 중 Enter 처리:** Chrome은 `compositionend` 없이 줄바꿈 입력을 먼저 보내는 경우가 있습니다(검증 중 실제로 관찰됨). 이때는 조합 글자를 먼저 강제 확정하고, 뒤늦게 도착하는 `compositionend`는 중복 삽입하지 않도록 무시합니다.

## 출력 (4단계)

데모 상단 두 번째 줄에서 형식·배율·투명 배경·범위(전체 / 현재 장 / 선택한 장)를 고르고 "내보내기"를 누릅니다. 데모에서는 프레임 하나가 한 장이고, 선택은 각 프레임 제목의 체크 상자입니다.

| 형식 | 방식 |
|---|---|
| PNG / WebP | 투명 배경 가능. 배율 1–4x |
| JPG | 투명을 지원하지 않아 흰 바탕을 깝니다 |
| PDF (래스터, 기본) | 장마다 이미지 한 장(pdf-lib). 쪽 크기는 CSS px 기준(1px = 0.75pt), 해상도 = 96 × 배율 dpi. 이미지는 PNG(무손실, 기본) 또는 JPG |
| PDF (벡터) | 인쇄용 HTML 문서를 만들어 브라우저 인쇄로 PDF 저장. 글자가 글자로 남고 글꼴이 포함됩니다. 장마다 크기가 달라도 됩니다(이름 붙은 `@page`) |

**래스터화 원리:** 장의 DOM을 SVG `<foreignObject>`에 넣어 이미지로 불러온 뒤 캔버스에 그립니다. 화면과 같은 브라우저 렌더러가 그리므로 CSS 꾸밈이 그대로 나옵니다. snapdom·html-to-image와 같은 원리이고, 우리 렌더러의 DOM은 스타일이 모두 인라인이라 이 라이브러리들의 핵심 기능(계산된 스타일 복사)이 필요 없어 직접 구현했습니다(`export.js` 약 250줄). 조건 세 가지:
- **이미지와 글꼴을 data URL로 넣어야 합니다.** SVG 이미지는 외부 자원을 불러오지 못하고, 페이지에 불러온 웹 글꼴도 보지 못합니다(설치된 시스템 글꼴만 보임).
- **SVG는 data URL로 불러옵니다.** `blob:` 주소로 불러오면 Chrome이 캔버스를 오염 상태로 표시해 PNG로 꺼낼 수 없습니다(실제로 확인).
- **배율은 `viewBox`로 줍니다.** CSS `zoom`도 시험했지만 배치 반올림이 달라져 화면과의 차이가 더 컸습니다(64 넘게 다른 픽셀 0.65% → 1.7%).

**글꼴 넣기(`fonts.js`):**
- 업로드 글꼴은 `fonts.register(이름, 파일 내용)`으로 등록합니다(화면에도 적용).
- 페이지 스타일시트의 `@font-face`(구글 폰트 등)는 규칙을 읽어 파일을 받아 넣습니다. 교차 출처 스타일시트는 `<link crossorigin>`이 있어야 읽힙니다(index.html에 추가함).
- 실제로 쓴 글꼴만 넣습니다. 글자 범위로 나뉜 글꼴(구글 폰트의 한글 조각)은 쓴 글자가 들어 있는 조각만 넣습니다.

**출력용 장:** `editor.exportPage()` → `{ w, h, render() }`. `render()`는 확정된 문서만으로 새로 배치·렌더하므로 커서·선택·조합 미리보기·디버그 표시가 들어가지 않습니다. 이후 캔버스 전체(배경·도형·이미지 요소)도 같은 모양을 구현하면 그대로 출력됩니다.

**파일 이름:** `{프로젝트명}_{장번호}.{확장자}`. 장이 10장 이상이면 번호 자릿수를 맞춥니다(`_01`, `_02` … 파일 목록 정렬용). 파일 이름에 쓸 수 없는 문자(`\ / : * ? " < > |`)는 `_`로 바꿉니다. PDF는 `{프로젝트명}.pdf`.

**저장(웹판):** 여러 장이면 폴더 선택(File System Access API)으로 저장합니다. 폴더 선택이 없거나 실패하면 zip으로 내려받습니다(fflate, 이미 압축된 형식이라 무압축 저장). 한 장이면 그대로 내려받습니다. Electron판은 아래 5단계 참고.

**벡터 PDF:** 웹판은 `printVector()`가 숨긴 iframe에서 인쇄 대화상자를 엽니다(사용자가 "PDF로 저장" 선택). Electron판은 인쇄 창 없이 바로 파일로 저장합니다(5단계).

**캔버스 크기 한계:** 가로·세로 32,767px, 넓이 268,435,456px를 넘는 배율은 "배율을 낮추라"는 오류로 막습니다.

## Electron (5단계)

### 구조: 웹판과 같은 렌더러

Electron 창은 `index.html`(편집기), `demo.html`, `app/`, `src/`, `vendor/`, `demo/`, `res/`를 **수정 없이 그대로** 불러옵니다(6단계 기준 37개 파일이 바이트 단위로 같음을 확인). 웹판과 다른 코드는 두 곳뿐입니다.

- `electron/` — 메인 프로세스(창·메뉴·파일 저장)와 preload. 렌더러에서는 보이지 않습니다.
- `src/platform.js` — `window.native`가 있으면 Electron, 없으면 웹판으로 동작하는 함수 모음. 데모(`demo/main.js`)는 저장·PDF·메뉴를 모두 이 파일을 통해 부릅니다.

**`app://` 주소로 불러오는 이유:** ES 모듈과 import map은 `file://`에서 동작하지 않습니다. 그래서 전용 주소 체계 `app://bundle/`을 등록해 파일을 내보냅니다. 이 주소는 '보안 컨텍스트'(HTTPS와 같은 대우)라 시스템 글꼴 API·클립보드 API 조건을 만족하고, 같은 출처라 출력 때 캔버스가 오염되지 않습니다(PNG로 꺼낼 수 있음). 내보내는 폴더는 위 네 항목뿐이라 렌더러가 `electron/`, `node_modules/`, `package.json`을 읽을 수 없습니다.

### 네이티브 대화상자

| 경우 | 동작 |
|---|---|
| 한 장(PNG·JPG·WebP) / 래스터 PDF | 파일 저장 대화상자. 기본 이름은 4단계 규칙(`{프로젝트명}_{장번호}`, `{프로젝트명}.pdf`). 확장자 없이 입력하면 붙입니다. 같은 이름이면 운영체제가 덮어쓸지 묻습니다 |
| 여러 장 | 폴더 선택 대화상자 → 같은 이름 파일이 있으면 "N개가 이미 있습니다. 덮어쓰시겠습니까?"(목록 10개까지 표시, 기본 선택은 취소) |
| 벡터 PDF | 파일 저장 대화상자 → 인쇄 창 없이 `printToPDF`로 바로 저장 |
| 취소 | 아무 파일도 쓰지 않음. 벡터 PDF는 인쇄용 숨긴 창도 만들지 않음 |

- **안전한 쓰기:** 임시 파일에 쓴 뒤 이름을 바꿉니다. 쓰는 도중 실패해도 기존 파일이 반쯤 덮이지 않고, 임시 파일도 남지 않습니다.
- **벡터 PDF 과정:** 렌더러가 `buildPrintHTML()`로 인쇄 문서를 만들어 넘기면, 메인 프로세스가 숨긴 창에 불러와 글꼴·이미지가 준비된 뒤 `printToPDF({ preferCSSPageSize: true, printBackground: true })`로 PDF를 만들고 창을 닫습니다. 인쇄 문서 창은 스크립트·외부 자원 금지(CSP)입니다.

### 편집 메뉴와 단축키

| 메뉴 | 동작 |
|---|---|
| 되돌리기 / 다시 실행 | 전역 되돌리기 스택(`History`). 포커스가 편집기 밖이어도 동작. 조합 중이면 조합 글자를 먼저 확정한 뒤 되돌림. 되돌릴 것이 없으면 메뉴 항목이 비활성화됨 |
| 잘라내기 / 복사 / 붙여넣기 | 운영체제 기본 동작 → 편집기의 copy/cut/paste 이벤트(3단계 클립보드 처리 그대로) |
| 서식 없이 붙여넣기 | 편집기에 '서식 없이' 표시를 켠 뒤 붙여넣기 이벤트를 부름 |
| 전체 선택 | 포커스된 편집기의 문서 전체 |
| 파일 → 내보내기… | 데모의 내보내기 버튼과 같음(단축키 없음) |

- **단축키는 렌더러의 keymap 한 곳에서만 처리합니다.** 메뉴에는 단축키를 표시만 하고 등록하지 않습니다(`registerAccelerator: false`). 그래서 사용자가 단축키를 재지정해도 메뉴와 충돌하지 않고, 키 한 번에 두 번 실행될 여지가 없습니다. 예외는 잘라내기·복사·붙여넣기로, macOS에서는 Cmd+C/V가 메뉴를 거쳐야만 동작하기 때문에 운영체제 기본 역할(role)을 씁니다.
- **Mod+Shift+V(서식 없이 붙여넣기):** Electron에서는 운영체제별 기본 키 동작에 맡기지 않고 편집기가 직접 붙여넣기 이벤트를 부릅니다(`CanvasEditor`의 `nativePaste` 옵션). macOS는 메뉴 없이는 Cmd+Shift+V가 붙여넣기 이벤트를 내지 않기 때문입니다. 웹판은 기존대로 브라우저 기본 동작.
- **확대/축소 메뉴 역할은 넣지 않았습니다.** Electron 기본 메뉴의 Ctrl+0/Ctrl+±는 페이지 전체 배율을 바꾸는데, Ctrl+0/1은 이후 캔버스 줌 단축키로 쓸 예정이라 겹칩니다.

### 시스템 글꼴(Local Font Access API)

Electron에서 동작합니다. `platform.listSystemFonts()` → 글꼴 이름별로 묶은 목록, 각 글꼴의 `data.blob()`으로 파일 내용도 읽힙니다(이후 프로젝트 파일에 글꼴을 넣을 때 사용). 웹판도 같은 함수이며, 처음 부를 때 권한 요청 창이 뜨므로 버튼 클릭 안에서 불러야 합니다.

- **권한:** Electron은 기본으로 모든 권한 요청을 허용하므로, 메인 프로세스에서 `local-fonts`와 클립보드 쓰기만 허용하고 나머지(위치·카메라·알림 등)는 거부합니다.
- **권한이 거부되면 예외가 아니라 빈 목록이 옵니다**(Chromium 152에서 확인). 데모는 "0개 (권한이 거부되었거나…)"로 표시합니다.
- **시스템 글꼴은 출력에 넣지 않아도 보입니다:** SVG 이미지 래스터화는 설치된 글꼴을 볼 수 있으므로 PNG 출력 = 화면이었습니다. 다른 컴퓨터에서 프로젝트를 열 때를 위한 글꼴 포함은 저장 단계에서 다룹니다.
- 데모 상단의 "시스템 글꼴 불러오기" → 목록에서 고르면 마지막으로 편집한 장의 선택 범위에 적용됩니다.

- Electron 문제가 아닙니다. 일반 Chrome 148(headless)에서도 똑같은 수치가 나옵니다. Electron의 **화면**은 Chromium 141의 화면과 픽셀까지 같고, 바뀐 것은 SVG 이미지 안 글자를 그리는 방식입니다.
- 다른 곳은 사선·곡선 획(`/`, `(`, `:`)과 선 장식(외곽선 글자·물결 밑줄·취소선)의 **가장자리 흐림 처리**뿐입니다. 글꼴과 위치는 같습니다(1px 이웃 허용 비교에서 64 넘게 다른 픽셀 0.05% 미만).
- Chromium 실행 옵션(서브픽셀 위치 끄기, GPU 끄기, 배율 고정)과 `text-rendering` 값으로는 달라지지 않았습니다.
- 그래서 `export.py`·`electron.py`의 판정을 "완전 일치"에서 **"위치 일치(이웃 허용 64 초과 0.05% 미만) + 가장자리 차이 0.3% 미만"**으로 바꿨습니다(2x 이상은 0.1% 미만). Chromium 141에서는 여전히 0이 나오고, 글꼴을 넣지 않은 경우(0.75%)는 계속 실패로 잡힙니다. `LE_CHROMIUM=…/chrome python3 test/export.py`로 Chrome 148에서도 38/38 통과.
- 웹판·Electron판이 같은 출력 방식을 쓰는 설계를 유지했습니다. Electron 전용으로 화면을 직접 캡처하는 방식(`capturePage`)을 쓰면 화면과 완전히 같게 만들 수 있지만, 웹판과 출력이 달라지므로 쓰지 않았습니다.

### 실제 환경에서 확인이 필요한 항목 (5단계)

리눅스 컨테이너에서는 Windows·macOS 실행 파일을 실행할 수 없어 다음은 직접 확인이 필요합니다.

**Windows** (`npm run dist:win` 또는 GitHub Actions 결과의 `.exe`)
1. 설치 → 실행 → 제거. SmartScreen 경고 후 실행되는지, 시작 메뉴·바탕화면 바로가기
2. 편집 메뉴와 단축키: Ctrl+Z / Ctrl+Shift+Z / Ctrl+Shift+V가 **한 번만** 실행되는지(리눅스에서는 실제 키 입력으로 확인함)
3. 내보내기: 폴더 선택·저장 대화상자, 한글 파일 이름, 같은 이름 덮어쓰기 확인. 다른 프로그램에서 연 파일을 덮어쓸 때 오류 메시지
4. 벡터 PDF를 Edge·Acrobat에서 열었을 때 모양(특히 외곽선·그라디언트 글자)
5. 시스템 글꼴 목록에 한글 글꼴이 어떤 이름으로 나오는지(예: 맑은 고딕이 `Malgun Gothic`인지 한글 이름인지)
6. 디스플레이 배율 125%·150%에서 화면과 출력 비교(검증은 배율 100% 기준)
7. 3단계·IME 항목(한글 조합, OS 클립보드를 거친 워드·구글 문서 복사/붙여넣기)은 Electron에서도 같은 코드이므로 Electron판으로 확인하셔도 됩니다

**macOS** (GitHub Actions 결과의 `.dmg`)
1. 서명 없는 앱 열기(시스템 설정의 "그래도 열기", 필요 시 `xattr -cr`)
2. Cmd+C / Cmd+V / Cmd+Z / Cmd+Shift+V가 한 번씩 동작하는지(macOS는 메뉴를 거치는 경로가 달라 가장 확인이 필요)
3. 앱 메뉴(나비글쓰기 → 종료 등) 항목 이름 — Electron 표준 항목(`role: 'appMenu'`)을 썼으며 영어로 나올 수 있습니다

## 편집기 화면 (6단계)

편집기 전체 UI의 첫 단계입니다. 한 장 위에서 글상자·도형·이미지 요소를 만들고 다루는 부분까지 만들었습니다. 도구 막대는 기능 확인용 임시 구성이며, 화면 배치·모양은 따로 정하실 부분입니다.

### 조작

| 입력 | 동작 |
|---|---|
| 도구 + 끌기 | 끈 크기로 만들기. 클릭만 하면 기본 크기. Shift = 정사각형·정원. 만든 뒤 선택 도구로 돌아감 |
| 글상자 도구 | 만들자마자 편집 모드(바로 입력) |
| 클릭 / Shift+클릭 | 선택 / 선택에 더하기·빼기. 그룹 안 요소를 누르면 그룹이 선택됨 |
| 빈 곳에서 끌기 | 범위 선택(걸친 요소 모두). Shift = 기존 선택에 더하기 |
| 끌기 | 이동. Shift = 가로 또는 세로로만. Alt = 스냅 끄기 |
| 모서리·변 핸들 | 크기 조절. 반대편이 고정. Shift = 비율 유지, Alt = 중심 고정. 회전된 요소는 자기 축 방향으로 |
| 위쪽 동그라미 핸들 | 회전(중심 기준). Shift = 15° 단위 |
| 여러 개 선택 후 핸들 | 선택 전체 상자 기준으로 함께 늘리기·회전 |
| 글상자 더블클릭 / Enter | 편집 모드(더블클릭은 누른 자리에 커서, Enter는 글 끝). Esc 또는 바깥 클릭 = 편집 끝 |
| 휠 / Shift+휠 / Ctrl+휠 | 세로 이동 / 가로 이동 / 커서 기준 확대·축소 |
| Space+끌기, 가운데 버튼 끌기 | 화면 이동 |
| 이미지 파일 끌어 놓기·붙여넣기, 도구 막대 "이미지" | 이미지 요소(기본 크기: 원본과 장의 60% 중 작은 쪽) |
| 편집 중이 아닐 때 글자 붙여넣기 | 새 글상자 |

**스냅(자동 맞춤):** 옮길 때 선택 상자의 왼쪽·가운데·오른쪽(위·가운데·아래)을 장 가장자리·중심, 다른 요소의 가장자리·중심에 화면 기준 6px 안이면 맞추고 분홍 안내선을 그립니다. 크기 조절 중에는 움직이는 변을 맞춥니다(회전 없는 상자, Shift·Alt를 누르지 않았을 때).

**넘친 글상자:** 글이 상자에 다 들어가지 않으면 오른쪽 아래에 빨간 + 표시.

### 단축키 (캔버스, 글상자 편집 중이 아닐 때)

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| V / T / R / O | 선택 / 글상자 / 사각형 / 원 도구 | Ctrl+D | 복제(+10px) |
| Delete, Backspace | 삭제 | Ctrl+G / Ctrl+Shift+G | 그룹 / 그룹 해제 |
| 방향키 / Shift+방향키 | 1px / 10px 이동(이어서 누르면 되돌리기 한 단위) | Ctrl+] / Ctrl+[ | 앞으로 / 뒤로 |
| Ctrl+A | 모두 선택(숨김·잠금 제외) | Ctrl+Shift+] / Ctrl+Shift+[ | 맨 앞 / 맨 뒤 |
| Ctrl+C / X / V | 요소 복사 / 잘라내기 / 붙여넣기(+10px씩) | Ctrl+Shift+L / Ctrl+Shift+H | 잠금 / 숨김 켜고 끄기 |
| Esc | 편집 끝 → 선택 도구 → 선택 해제 | Ctrl+0 / Ctrl+1 | 화면에 맞춤 / 100% |
| Enter | 선택한 글상자 편집 | Ctrl+= / Ctrl+- | 확대 / 축소(1.25배) |
| Ctrl+Z / Ctrl+Shift+Z | 되돌리기 / 다시 실행 | Ctrl+E | 내보내기 |

- 글상자 편집 중에는 편집기 단축키(3단계)가 먼저 처리하고, 캔버스 단축키 중에서는 Esc·확대/축소·내보내기만 동작합니다(Delete·V·Ctrl+D 등은 글 편집으로 들어감).
- 재지정: `createKeymap({ 'Mod-Shift-d': 'duplicate', 'Mod-d': null }, APP_KEYMAP)`. 한글 자판 상태에서도 물리 키로 찾습니다(ㄱ → R 확인).
- 요소 복사는 HTML 안에 요소 JSON(`data-nabitext`)을 넣어 시스템 클립보드로 보냅니다. 편집기 창을 두 개 열어도 서로 붙여넣을 수 있고, 다른 프로그램에는 글상자 글자만 텍스트로 갑니다.

### 구조

- **문서 모델(`app/model.js`):** 장 → 요소 트리. 요소는 `x, y, w, h`(회전 전 상자)와 `rotation`(도, 중심 기준), `opacity`, `blend`(혼합 모드), `locked`, `hidden`. 그룹은 자식을 담고, 자식 좌표는 장 기준 절대 좌표입니다(그룹을 옮기면 자식 좌표가 바뀜). 배열 순서 = 아래 → 위.
- **되돌리기:** 요소 변경은 `ModelEntry`(요소 트리 전/후 스냅숏), 글자 변경은 기존 `TextEntry`가 같은 전역 스택에 쌓입니다. 글상자를 지워도 편집기 객체는 남겨 두어, 삭제를 되돌린 뒤 그 이전의 글자 입력도 이어서 되돌릴 수 있습니다.
- **글상자 편집:** 요소마다 3단계 편집기(`CanvasEditor`)가 붙어 있습니다. 확대·회전 상태에서 클릭 위치를 맞추려고 편집기에 좌표 변환 함수(`toLocal`)를 넘깁니다. 글상자 크기는 정수 px로 맞춥니다(영역 마스크가 픽셀 단위). 사각형 글상자는 영역을 경로로 그리지 않고 바로 채워 리사이즈 중 매번 다시 만들어도 빠릅니다.
- **출력:** `view.exportPage()`가 화면과 같은 함수로 요소 DOM을 새로 만듭니다(선택 상자·커서 없음). 4단계 출력(PNG·JPG·WebP·PDF)에 그대로 넘깁니다. 출력 DOM에는 앱 스타일시트가 없으므로 요소 스타일은 모두 인라인입니다.

## 레이어·속성 패널 (7단계)

왼쪽에 레이어 패널, 오른쪽에 속성 패널을 붙였습니다. 패널 폭·배치·모양은 기능 확인용 임시 구성입니다.

### 레이어 패널

| 입력 | 동작 |
|---|---|
| 행 클릭 / Ctrl(⌘)+클릭 / Shift+클릭 | 선택 / 더하기·빼기 / 보이는 행 순서로 범위 선택. 캔버스 선택과 서로 연동 |
| ▸ | 그룹 펼치기·접기. 캔버스에서 그룹 안 요소가 선택되면 자동으로 펼침 |
| 이름 더블클릭 | 이름 바꾸기(Enter 적용, Esc 취소, 비우면 기본 이름) |
| 눈·자물쇠 | 숨김·잠금 켜고 끄기(마우스를 올리면 보이고, 켜진 것은 항상 보임) |
| 끌어 놓기 | 행의 위쪽 절반 = 그 요소 앞, 아래쪽 절반 = 뒤, 그룹 행의 가운데 = 그룹 안 맨 앞, 목록 아래 빈 곳 = 맨 뒤 |
| 행에 마우스 올리기 | 캔버스에 그 요소 윤곽 표시 |

- 위 = 앞(나중에 그리는 요소). 패널에서는 그룹 안 요소도 직접 선택할 수 있습니다(캔버스 클릭은 그룹 전체를 선택).
- 그룹을 비우면 그룹은 지워집니다. 그룹을 자기 안이나 자손 안으로 옮길 수는 없습니다.

### 속성 패널

| 선택 | 칸 |
|---|---|
| 없음 | 장: 너비·높이·배경(비우면 투명) |
| 요소 | 배치: X·Y·W·H(여러 개·그룹은 전체 상자 기준, 바꾸면 함께 늘어남), 회전(요소 하나일 때). 모양: 불투명도·혼합 모드 |
| 도형만 | 채움(비우면 없음)·테두리 색·두께·모서리(사각형) |
| 이미지만 | 맞춤: 늘이기·맞추기·채우기 |
| 글상자 포함 | 글꼴·크기·자간·행간, 굵게·기울임·밑줄·취소선, 색·형광펜, 정렬 4종, 안쪽 여백 |

- **글자 속성 대상:** 편집 중이면 선택한 글자(빈 선택이면 다음에 입력할 글자), 편집 중이 아니면 선택한 글상자 전체. 제목에 "(선택한 글자에)" / "(글상자 전체에)"로 표시합니다. 글상자 여러 개를 한 번에 바꿔도 되돌리기는 한 단위이고, 되돌려도 편집 모드로 들어가지 않습니다.
- **값이 섞여 있으면** 칸이 비고 "여러 값"이 흐리게 보입니다. 글자에 꾸밈이 없으면 글상자 기본값(크기 32 등)을 보여 줍니다.
- **숫자 칸:** Enter·다른 곳 누르기 = 적용, Esc = 취소, ↑↓ = 1씩(Shift = 10씩). 이어서 누른 화살표와 색 고르기 창을 끌며 바꾼 색은 되돌리기 한 단위입니다. 적용한 뒤에는 키보드가 캔버스(편집 중이면 글상자)로 돌아갑니다.
- **바뀐 것이 없는 조작은 되돌리기에 기록하지 않습니다**(예: 같은 값으로 다시 확정).
- **글꼴:** 목록에서 고르거나 이름을 직접 입력합니다. "시스템 글꼴" 버튼으로 설치된 글꼴을 목록에 불러옵니다(웹판은 첫 사용 때 권한 요청 창).

## 여러 장·저장·복구 (8단계)

### 여러 장

왼쪽 위 "장" 목록: 클릭 = 그 장으로, 더블클릭 = 이름 바꾸기, 끌어 놓기 = 순서, ＋ = 지금 장 뒤에 같은 크기·배경의 새 장, 복제, 삭제(마지막 한 장은 지울 수 없음). 장 추가·복제·삭제·순서는 되돌리기 한 단위입니다. **다른 장에서 한 변경을 되돌리면 그 장으로 넘어가서** 되돌립니다(요소 변경·글 입력 모두).

내보내기에 범위(현재 장 / 모든 장)를 넣었습니다. 파일 이름의 장 번호는 프로젝트 안 순서입니다(현재 장이 셋째 장이면 `_3`).

### 프로젝트 파일(.nabi)

| 동작 | 단축키 | 내용 |
|---|---|---|
| 새로 만들기 | Ctrl+N (Electron판만) | 저장하지 않은 변경이 있으면 먼저 확인(저장 / 저장하지 않음 / 취소) |
| 열기 | Ctrl+O | 같은 확인 후 열기 창 |
| 저장 | Ctrl+S | 처음에는 저장 창, 그 뒤로는 같은 파일에 바로 |
| 다른 이름으로 저장 | Ctrl+Shift+S | 항상 저장 창 |

- **형식:** zip 안에 `project.json`(장·요소·글상자 문서·스와치·글꼴 목록)과 `assets/<해시>.<확장자>`(이미지·글꼴 원본). 이미 압축된 PNG·JPG·WebP·WOFF는 다시 압축하지 않습니다.
- **프로젝트 이름 = 파일 이름.** 제목 줄에 `● 이름 — 나비글쓰기`로 보이며 ●는 저장하지 않은 변경이 있다는 뜻입니다.
- **웹판:** Chrome의 파일 저장·열기 창(File System Access API)을 씁니다. 한 번 저장한 파일은 같은 탭에서 창 없이 다시 저장됩니다. 창을 지원하지 않는 브라우저는 내려받기·파일 고르기로 대신합니다. **Ctrl+N은 브라우저가 먼저 가져가(새 창) 웹판에서는 동작하지 않습니다**(도구 막대 "새로" 버튼 사용).
- **Electron판:** 네이티브 저장·열기 창, 파일 메뉴(새로 만들기·열기·저장·다른 이름으로 저장·내보내기). 설치 파일에 `.nabi` 파일 연결을 넣어 탐색기에서 더블클릭하면 열립니다(이미 실행 중이면 기존 창에서). 저장하지 않은 변경이 있을 때 창을 닫으면 저장 / 저장하지 않음 / 취소를 묻습니다.
- **보안:** Electron에서 렌더러는 저장할 경로를 직접 정할 수 없습니다. 메인 프로세스가 대화상자·파일 연결로 받은 경로만 기억해 그 경로에만 씁니다. 열 때는 zip 안 에셋의 내용 해시를 다시 계산해 파일 이름과 맞지 않으면 열지 않습니다. 알 수 없는 요소 종류는 버리고 숫자 값은 보정합니다.

### 에셋 라이브러리

이미지 요소, 글상자 안 이미지, 붙여넣은 이미지(파일·다른 프로그램의 HTML·원격 주소), 업로드 글꼴이 모두 에셋 저장소를 거칩니다. 내용 해시(SHA-256 앞 32자)로 구분해 **같은 파일은 몇 번을 넣어도 하나만** 저장합니다. 작업 중에는 에셋의 `blob:` 주소를 쓰고 저장할 때 `assets/…` 경로로 바꿉니다. 이것으로 3단계에서 남긴 "복사한 이미지 주소가 `blob:`이라 같은 실행 중에만 유효", "외부 HTML의 원격 이미지는 원래 주소 그대로" 문제를 해결했습니다(가져올 수 없는 원격 주소는 원래 주소로 남기고 저장할 때 알려 줍니다).

### 업로드 글꼴

속성 패널 위 "글꼴 파일"로 .ttf·.otf·.woff·.woff2를 넣으면 프로젝트에 포함됩니다. 글꼴 이름 = 파일 이름(확장자 제외). 다른 컴퓨터에서 열어도 같은 글꼴로 보이고, 출력(PNG·PDF)에도 들어갑니다.

### 자동 저장·비정상 종료 복구

- 마지막 변경 뒤 **2초**가 지나면 브라우저 내장 저장소(IndexedDB)에 복구용 사본을 씁니다. 에셋은 한 번만 씁니다. **실제 프로젝트 파일은 건드리지 않습니다.**
- 다음 실행 때 사본이 있으면 "저장하지 않은 작업이 남아 있습니다 … 복구 / 버리기"를 묻습니다. 복구한 내용은 아직 파일에 저장되지 않은 상태(●)로 열립니다.
- 사본은 저장하거나, 새로 만들기·열기, 창을 닫을 때 "저장하지 않음"을 고르면 지웁니다. Electron에서 화면 프로세스가 비정상 종료되면 알림 후 다시 불러오고, 이때 같은 복구 확인이 뜹니다.

4. 큰 사진이 많은 프로젝트(수백 MB)의 저장·자동 저장 속도

## 도구·이미지·모양 글상자·경로 글자 (9단계)

### 도구
- **펜(P):** 클릭 = 모서리 점, 끌기 = 곡선 점(끈 방향이 핸들), 첫 점 클릭 = 닫힌 패스, 더블클릭·Enter·Esc = 열린 패스로 끝. 끝나면 선택 도구로 돌아갑니다.
- **선(L):** 끌어서 직선 패스. Shift = 45° 단위.
- **다각형:** 끌어서 6각형. 속성 패널에서 다각형/별, 변 개수, 별의 안쪽 비율을 바꿉니다.
- **점 편집:** 패스를 더블클릭(또는 속성 패널 "점 편집"). 점 끌기 = 옮기기, 핸들 끌기 = 곡선, Delete = 점 지우기, Enter·Esc = 끝. 편집 중 화살표·Delete는 요소가 아니라 점에 작동합니다.

### 이미지
- **자르기:** 이미지 더블클릭(또는 "자르기"). 테두리 핸들 = 보일 범위, 안쪽 끌기 = 원본을 움직여 보이는 부분 바꾸기. 원본 밖으로는 나가지 않습니다. "자르기 해제" = 원본이 있던 자리에 원본 전체.
- **필터:** 밝기·대비·채도·색조·흐림·흑백·세피아·반전(CSS 필터). "필터 초기화".
- **마스크:** 이미지 + 도형(또는 패스)을 함께 선택 → "도형으로 마스크"(도형은 마스크가 되고 지워짐). "알파 마스크 이미지…" = 고른 이미지의 투명한 곳을 가림. "마스크 해제".

### 채움
도형·패스의 채움: 단색 / 선형 그라디언트(각도, 두 색) / 원형 그라디언트 / 패턴(이미지 반복, 배율). 패턴·알파 마스크 이미지도 에셋으로 저장됩니다.

### 모양 글상자
글상자 속성 "모양": 사각형 / 원 / 도넛(안쪽 구멍 %) / 이미지 외곽선. 도형·패스와 함께 선택 → "도형 모양으로 글상자"(그 모양 안에 글, 도형은 지워짐).
- 이미지 외곽선: 판정 = 투명도(임계값) 또는 배경색(색 + 허용 오차). 이미지 보이기·불투명도, 다듬기, 최소 구간, 반전(모양 바깥에 글).
- 공통: 글상자의 안쪽 여백이 모양에서 글까지 거리입니다.

### 경로 글자
도형·패스 선택 → "경로 글자로"(원래 요소가 경로 글자로 바뀜). 속성: 글, 시작 위치(%), 정렬(시작/가운데/끝), 글꼴·크기·색, 경로 보이기. 원·타원에서 만들면 9시 방향에서 시계 방향으로 도는 경로가 되어, 시작 위치 25%·가운데 정렬로 **위쪽 가운데에 바로 선 글**이 됩니다.

화면은 글자 폭을 픽셀 단위로 맞추고 출력·인쇄는 소수 폭을 써서, 긴 경로 글자는 양 끝에서 최대 4px가량 어긋났습니다. 글꼴 설계 폭으로 잰 전체 길이를 SVG `textLength`로 고정해 세 경로(화면·이미지 출력·벡터 PDF)가 같은 자리에 글자를 놓게 했습니다(글자별 어긋남 4px → 1px 이하).

## 글 흐름·프리셋·보조선·템플릿 (10단계)

### 이어진 글상자
- 글이 넘친 글상자의 오른쪽 아래 바깥에 **빨간 +(출구)** 가 나옵니다. 누르면 잇기 모드가 되고, 다른 글상자를 누르면 그 글상자로 이어집니다. 빈 곳을 누르면 같은 크기의 새 글상자가, 끌면 그린 크기의 새 글상자가 만들어져 이어집니다. Esc는 취소입니다.
- 글상자 두 개를 선택하면 속성 패널에 **"글상자 잇기"** 가 나옵니다. 먼저 고른 글상자에서 나중 고른 글상자로 이어집니다.
- 이어진 글상자를 선택하면 순서(1/3, 2/3 …)와 흐름 선이 보입니다. **"이어짐에서 빼기"** 를 누르면 그 글상자는 빈 글상자로 남고, 글은 나머지 글상자로 흐릅니다.
- 편집: 어느 글상자에서든 바로 씁니다. 커서·선택·↑↓ 이동·끌어 선택이 글상자 사이를 넘나듭니다. 한글 조합 입력창도 커서가 있는 글상자를 따라갑니다.
- 구조: 이어진 글상자들은 문서 하나("이야기")를 나눠 담습니다. 글상자 속성 `story`(이야기 id)·`seq`(순서)로 묶고, 저장 파일에서는 이야기의 첫 글상자만 문서를 가집니다. 엔진은 앞 글상자가 넘친 문서 위치부터 다음 글상자를 배치합니다(`layoutChain`).

### 넘치면 글자 줄이기(자동 축소)
속성 패널 "글 흐름"의 **"넘치면 글자 줄이기"**. 다 들어갈 때까지 글자 크기와 자간을 같은 배율로 줄입니다(최소 배율까지. 1/256 단위로 찾음). 이어진 글상자에서는 마지막 글상자까지 채우고도 넘칠 때만 줄입니다. 지금 배율은 "글자 82%로 줄임"처럼 표시됩니다.

### 스타일 프리셋
속성 패널 "스타일 프리셋". 프리셋은 **문단**에 겁니다.
- **새 프리셋**: 커서 자리(글상자 전체를 골랐으면 첫 글자)의 글자 모양(글꼴·크기·굵기·기울임·색·행간·자간)과 문단 정렬·간격·들여쓰기로 만들고, 그 문단에 겁니다.
- **다시 정의**: 지금 글자 모양으로 프리셋을 고칩니다. 이 프리셋을 쓰는 모든 글상자의 문단이 바로 바뀝니다.
- 프리셋 목록은 프로젝트에 저장됩니다(project.json의 `styles`).

### 눈금자·가이드·격자
- **눈금자**: 캔버스 위·왼쪽. 선택한 요소의 범위가 파랗게 표시됩니다.
- **가이드**: 눈금자에서 캔버스로 끌어 만들고, 끌어 옮기고, 눈금자 위로 끌어 놓으면 지워집니다. 장마다 저장됩니다. 요소를 옮기거나 크기를 바꿀 때 가이드에 붙습니다.
- **격자**: 격자가 보이는 동안에만 격자에 붙습니다. 간격은 요소를 선택하지 않았을 때 속성 패널에서 바꿉니다.
- 도구 막대의 "눈금자·격자·가이드" 버튼, Electron판은 "보기" 메뉴에도 있습니다.

### 균등 간격 스냅
요소를 옮길 때, 같은 줄(가로) 또는 같은 열(세로)에 있는 요소들 사이에 이미 있는 간격과 같아지는 자리에 붙습니다. 두 요소 사이에 두면 양쪽 간격이 같아지는 자리에 붙습니다. 분홍 선과 숫자로 같은 간격이 표시됩니다. Alt를 누르고 옮기면 붙지 않습니다(기존 스냅과 같음).

### 템플릿
- 장 목록의 **"템플릿"** 버튼 → 템플릿 창: "지금 장을 템플릿으로…", 목록의 "새 장으로"·"파일로"·"지우기", "파일에서 가져오기…".
- 템플릿은 **이 컴퓨터의 템플릿 보관함**(브라우저·Electron 앱의 내부 저장소)에 저장됩니다. 다른 컴퓨터로 옮기려면 "파일로"(.nabitpl 파일)로 내보냅니다. 형식은 프로젝트 파일과 같은 zip입니다. 장 하나와 그 장이 쓰는 스타일 프리셋·업로드 글꼴이 들어갑니다.
- **슬롯**: 이미지·글상자를 선택하고 속성 패널 "템플릿 → 슬롯"을 켜면 바꿔 넣을 자리로 표시됩니다(주황 점선. 출력에는 안 나옴).
  - 이미지 슬롯: "이미지 바꾸기…"를 누르거나 이미지 파일을 슬롯 위에 끌어다 놓으면, 상자·필터·마스크는 그대로 두고 이미지만 바뀝니다.
  - 글 슬롯: 글상자를 편집해 글만 바꿉니다(프리셋·글자 모양 유지).
- 템플릿으로 만든 장은 지금 장 뒤에 들어갑니다. 템플릿의 프리셋은 프로젝트에 더해집니다(같은 id인데 내용이 다르면 새 id로). 되돌리기 한 번에 장과 프리셋이 함께 취소됩니다.

### 10단계에서 고친 것(이전 단계 기록 수정)
- **9단계에서 원인을 확정하지 못했던 "모양 글상자 일부 줄이 출력에서 1px 위"**: 캔버스 이동(패닝)에 CSS transform을 써서 생긴 문제였습니다. transform으로 옮기면 합성 레이어가 소수 px 위치에 놓이고, 글자 기준선 반올림이 출력과 달라집니다. 이동을 left/top으로 바꾸고 확대에만 transform을 쓰게 했습니다. 100%일 때는 장 원점을 화면 픽셀 경계에 맞춥니다. 이제 9단계 모양 글상자 출력은 화면과 차이 0입니다.
- **5단계의 "Chromium 148 이후 출력이 화면과 최대 0.21% 다름"**: Chromium 문제가 아니었습니다. 출력용 SVG에 문서 언어(`lang="ko"`)가 빠져 있어서, 이미지 안에서는 한글 글리프 선택이 화면과 달라졌습니다. 출력 SVG와 벡터 PDF용 HTML에 문서 언어를 넣었습니다. Electron(Chromium 152)의 PNG 1x 대조가 0.11% → 0으로 바뀌었습니다. 언어를 다시 빼 보면 0.11%가 다시 나와서, 이것이 원인임을 확인했습니다. 9단계 경로 글자의 차이(0.56%)도 같은 원인이었습니다. 판정 기준(이웃 허용 0.05%·가장자리 0.3%)은 그대로 두었습니다.
- 레이아웃 엔진이 줄마다 배열을 복사하던 곳을 없앴습니다(`onlySpaces`). 입력 1회 갱신의 최대값이 가끔 16ms를 넘던 것(가비지 수집 추정)이 8회 반복에서 모두 12ms 이하가 되었습니다.

## 여러 장에 흐르는 글·글자 프리셋·선택한 장 내보내기·배경 이미지·단축키 설정 (11단계)

### 여러 장에 흐르는 글
- 10단계의 이어진 글상자를 **다른 장의 글상자로도** 이을 수 있습니다.
  - 넘친 글상자의 출구(빨간 +)를 누른 뒤 장 목록에서 뒤쪽 장으로 가서, 그 장의 글상자나 빈 곳을 누르면 됩니다. 커서 옆에 "1장 글상자에서 잇는 중"이 보입니다.
  - 이어진 글상자의 마지막 것을 선택하면 속성 패널에 **"다음 장으로 이어 쓰기"** 가 나옵니다. 다음 장의 같은 자리에 같은 크기 글상자를 만들어 잇고, 다음 장이 없으면 새 장을 만듭니다. 되돌리기 한 번에 장·글상자·잇기가 모두 취소됩니다.
- **흐르는 순서 = 장 순서**(같은 장 안에서는 이은 순서). 장 목록에서 장 순서를 바꾸면 글의 흐름도 따라 바뀝니다. 그래서 앞쪽 장으로는 잇지 않습니다.
- 흐름 표시: 다른 장으로 이어지면 글상자 옆에 "→ 3장", 다른 장에서 오면 "2장에서 →"가 보입니다.
- 편집: 커서가 다른 장의 글상자로 넘어가면(↓ 이동, 입력으로 글이 밀림, 되돌리기) 편집을 끝내지 않고 그 장으로 화면이 넘어갑니다. 숨긴 입력창(한글 조합용)도 따라갑니다.
- 이야기의 첫 글상자가 있는 장을 지우면 다음 장의 글상자가 글을 처음부터 이어받습니다. 저장 파일에서는 이야기의 첫 글상자에만 문서가 들어갑니다.
- **켜고 끄기**: 설정의 **"다른 장의 글상자와 잇기"**. 끄면 같은 장 안에서만 잇고 "다음 장으로 이어 쓰기" 버튼도 사라집니다. 이미 여러 장에 걸쳐 이어진 글은 그대로 흐르고, 필요하면 "이어짐에서 빼기"로 끊습니다.

### 글자 스타일 프리셋
속성 패널 "스타일 프리셋"의 **글자 프리셋**. 고른 글자(편집 중이 아니면 글상자 전체)에 겁니다.
- 겹치는 순서: 글상자 기본 < 문단 프리셋 < 글자 프리셋 < 개별 꾸밈(크기·색 등을 따로 준 것).
- "새 글자 프리셋"은 고른 글자의 모양으로 만듭니다. "글자 프리셋 다시 정의"는 이 프리셋을 쓰는 모든 글자를 바꿉니다. 자동 축소 배율은 글자 프리셋 크기에도 곱해집니다.

### 선택한 장 내보내기
장 목록에서 **Ctrl(⌘)+클릭**으로 장을 하나씩 더하거나 빼고, **Shift+클릭**으로 범위를 고릅니다. 선택한 장은 번호에 파란 표시가 붙습니다. 내보내기 범위의 "선택한 장 (n)"으로 그 장들만 내보냅니다. 파일 이름의 장 번호는 프로젝트 순서를 따릅니다(1·3·4장 → _1, _3, _4).

### 장 배경 이미지
요소를 선택하지 않았을 때 속성 패널 "장"의 **"배경 이미지…"**. 맞춤은 채우기·맞추기·늘이기·바둑판 중에서 고릅니다. 요소가 아니라 장 속성이라 선택·이동되지 않습니다. 이미지는 에셋으로 저장되고, 템플릿에도 들어갑니다. 투명 출력에서는 장 배경색만 빠지고 배경 이미지는 남습니다.

## 큰 사진·공통 장·찾기·미리보기·되돌리기·자동 업데이트 (12단계)

### 큰 사진 축소본
- 가장 긴 변이 2560px보다 큰 사진(PNG·JPEG·WebP)은 넣을 때 화면용 축소본을 뒤에서 만들어 화면에 씁니다. **출력·저장은 늘 원본**입니다.
- 축소는 브라우저가 메인 스레드 밖에서 합니다(`createImageBitmap`). 여러 장이면 한 장씩 차례로 합니다.
- 프로젝트를 열면 축소본을 새로 만듭니다(파일에는 원본만 저장). 만드는 동안 그 자리는 비어 보이다가 준비되면 채워집니다.
- 이미지 외곽선 글상자의 외곽선도 축소본으로 계산합니다. 열 때마다 같은 축소본이 나오므로 줄 배치가 같습니다.
- 메모리(계산값): 4000×3000 사진 한 장을 풀어 둔 크기가 48MB에서 약 20MB로 줄어듭니다(가로×세로×4바이트).
- EXIF 방향(휴대폰 사진의 회전 정보)을 반영합니다(방향 6으로 확인).

### 공통 장·쪽 번호
- 장 목록 맨 위의 "공통 장"에 놓은 요소는 모든 장의 맨 뒤에 깔립니다. 장에서는 선택·편집되지 않고, 고치려면 공통 장으로 갑니다.
- 공통 장 글상자에 `{쪽}`을 쓰면 그 장의 쪽 번호, `{전체쪽}`은 마지막 쪽 번호로 바뀝니다. 편집 중 "쪽 번호 넣기"·"전체 쪽수 넣기" 버튼으로도 넣을 수 있습니다.
- 공통 장 속성 "첫 쪽 번호"로 시작 번호를 정합니다. 장 속성 "공통 요소 보이기"를 끄면 그 장(표지 등)에만 안 보입니다. 끈 장도 번호는 셉니다.
- 공통 장의 글은 공통 장 안에서만 잇습니다(다른 장과 잇기·다음 장으로 이어 쓰기 불가).

### 찾기·바꾸기 (Ctrl+F)
- 프로젝트 전체(장 순서 → 공통 장)의 글상자와 경로 글자에서 찾습니다. 이어진 글은 한 글로 찾습니다.
- 편집 중 고른 글자가 있으면 그것으로 시작합니다. Enter = 다음, Shift+Enter = 이전, 찾은 곳으로 장을 넘어 이동해 그 글자를 선택합니다.
- 찾는 동안 포커스는 찾기 칸에 남습니다. 글상자를 넘쳐 안 보이는 곳이면 그렇게 알립니다.
- 바꾸기 칸에서 Enter = 하나 바꾸기, Ctrl+Enter = 모두 바꾸기. **모두 바꾸기는 되돌리기 한 번에 전부 돌아갑니다.**
- 글자 모양이 섞인 단어도 찾습니다. 문단·강제 줄바꿈을 넘는 일치는 찾지 않습니다.

### 장 목록 미리보기
- 장마다 작은 그림(72×54 안)을 보입니다. 공통 장도 보입니다.
- 바뀐 장만 다시 그립니다. 마지막 입력·변경 뒤 0.6초 조용하고 브라우저가 한가할 때만, 한 장씩 그립니다.
- 그리는 작업은 한가한 틈마다 쪼개서 합니다(작업 하나가 가장 길어도 약 12–19ms). 끄거나 입력하기 시작하면 그리던 것을 버립니다.
- 사진은 가장 긴 변 256px 사본으로 그리고, 글은 지금 배치를 재사용합니다.
- 설정 창에서 끌 수 있습니다(끄면 목록이 예전처럼 한 줄씩).

### 되돌리기 기록 가볍게
- 기록 하나에 장 전체를 복사하던 것을, **바뀐 최상위 요소만** 담게 바꿨습니다. 되돌릴 때 나머지는 지금 장의 요소를 씁니다.
- 측정: 요소 300개 장에서 요소 하나씩 500번 바꾸면 기록 메모리가 **76MB → 1.6MB**였습니다. 바꾸는 속도·되돌리기 속도는 같았습니다(2.6초/500번, 0.7초/200번).

### 설치 파일·서명·자동 업데이트
- **자동 업데이트(설치판):**
  - 앱을 켜고 8초 뒤, 켜 둔 동안 6시간마다 새 버전을 확인해 내려받고, 앱을 끝낼 때 설치합니다. 작업 중에 끊지 않습니다.
  - 준비되면 오른쪽 아래 알림이 뜨고 "지금 다시 시작"을 누를 수 있습니다. 저장 안 한 변경이 있으면 먼저 저장을 묻습니다.
  - 설정 창 "업데이트 자동 확인"으로 끄고, 상태 확인·"지금 확인"도 할 수 있습니다. 도움말 메뉴 → 업데이트 확인으로도 확인합니다.

## 고친 것: Windows 설치판이 빈 화면으로 뜨던 것 (0.16.1)

- **증상:** Windows에서 설치판을 켜면 단추 아이콘·캔버스·속성 패널이 비어 있고 도구 단추가 왼쪽에 빈 칸으로 늘어섬.
- **원인:** GitHub의 Windows 빌드(또는 Windows에서 git으로 받은 폴더)에서는 git이 줄 끝을 CRLF로 바꿉니다. 그러면 `index.html` 안 import map의 해시(CSP 허용 목록)가 브라우저가 재는 값(줄 끝을 LF로 바꾼 뒤 잼)과 달라져 import map이 막히고, 프로그램 코드 전체가 불러와지지 않았습니다. 같은 상황을 여기서 재현해 확인했습니다.
- **고친 것:** CSP 해시를 잴 때 줄 끝을 LF로 맞춥니다(`electron/csp.js`). 저장소에 `.gitattributes`를 넣어 Windows에서 받아도 줄 끝이 LF로 남게 했습니다. 시험 `stage15` W1이 CRLF·LF 해시가 같은지 확인합니다.

## 태블릿(갤럭시 탭) (14단계)

안드로이드 태블릿의 크롬·삼성 인터넷에서 손가락과 S펜으로 쓰도록 했습니다. 웹판 주소로 열고, 홈 화면에 추가하면 앱처럼 전체 화면으로 열립니다.

### 손가락으로
| 동작 | 결과 |
|---|---|
| 톡 | 고르기(빈 곳이면 선택 해제) |
| 끌기 | 옮기기 / 빈 곳에서 끌면 범위 선택 |
| 손잡이 끌기 | 크기 조절·회전. 손가락일 때는 손잡이를 크게 그리고 조금 떨어져 눌러도 잡힘. 사진·여러 개의 모서리는 비율 유지(Shift 대신) |
| 두 번 톡 | 글상자 편집(누른 자리에 커서). 고른 글상자를 한 번 더 톡해도 편집 |
| 두 손가락 벌리기·오므리기 | 확대·축소(손가락 사이 지점 기준) |
| 두 손가락 끌기 | 화면 이동 |
| 두 손가락 톡 / 세 손가락 톡 | 되돌리기 / 다시 실행 |
| 글상자 편집 중 톡 / 끌기 / 두 번 톡 / 세 번 톡 | 커서 / 범위 선택 / 낱말 / 문단 |
| 레이어·장 줄 톡 / 길게 누르기 / 길게 누른 채 끌기 | 고르기 / 선택에 더하기·빼기(Ctrl 대신) / 순서 바꾸기 |
| 눈금자에서 끌기, 패널 가장자리 끌기 | 가이드 만들기, 패널 너비 |

- **S펜**은 마우스처럼 한 점으로 동작합니다(끌기·손잡이·글자 선택).
- 한 손가락이 닿은 뒤 곧 두 번째 손가락이 닿으면(아직 움직이지 않았으면) 한 손가락 동작을 취소하고 확대·이동으로 바꿉니다. 이미 끄는 중이면 그대로 끕니다.
- **화면 자판:** 글상자를 편집하면 손을 뗄 때 자판이 뜹니다. 자판이 올라와 캔버스가 줄어도 확대 비율은 그대로이고 커서가 보이도록 화면을 옮깁니다. 입력하며 커서가 내려가도 따라갑니다.
- 당겨서 새로 고침, 두 번 톡 확대, 길게 눌렀을 때 뜨는 메뉴는 막았습니다(작업이 날아가지 않게).

### 화면
- 손가락 화면(터치 화면)에서는 단추·칸·줄을 손가락 크기(대략 40px)로 키웁니다. 마우스를 쓰면 핸들은 다시 작게 그립니다.
- 위 막대에 **패널 단추** 두 개(장·레이어, 속성)가 생깁니다.
- **세로 화면 등 좁은 화면(1000px 이하):** 장·레이어 패널은 캔버스 위에 덮는 서랍이 됩니다(패널 단추로 열고, 캔버스를 누르면 닫힘). 속성 패널은 264px로 줄입니다. 보기 단추(눈금자·격자·가이드)는 자리가 모자라 숨깁니다(가로로 돌리면 다시 보임).

### 홈 화면 앱·인터넷 없이
- 웹판 배포 폴더(`npm run build:web`)에 `manifest.webmanifest`와 `sw.js`가 들어갑니다. 크롬에서 메뉴 → "홈 화면에 추가"(또는 "앱 설치")를 누르면 주소창 없이 전체 화면으로 열립니다.
- 한 번 연 뒤에는 인터넷이 끊겨도 열립니다. 인터넷이 있으면 늘 새 파일을 먼저 받으므로, 새 버전을 올리면 다음에 열 때 바로 바뀝니다.
- 서비스 워커는 https 주소(또는 localhost)에서만 등록합니다. Electron판과 개발 서버에서는 쓰지 않습니다.

### 태블릿에서 알아 둘 점
- **저장:** 안드로이드 크롬에는 저장 위치를 고르는 창이 없어서, 저장하면 "다운로드" 폴더로 내려받기가 됩니다(같은 이름이면 번호가 붙음). 작업 중에는 자동 저장이 계속 되므로 앱이 닫혀도 복구됩니다. 확인 필요: 크롬 버전에 따라 저장 창이 생겼을 수 있습니다.
- **시스템 글꼴 불러오기**는 안드로이드에서 되지 않습니다. 글꼴 파일 넣기는 됩니다.

## 점검 보완: 글꼴·안전·저장·자동 저장 (13단계)

### 글꼴 넣기·고르기
- **글꼴 이름은 파일 안 이름표에서 읽습니다**(TTF·OTF·TTC·WOFF). 파일 이름이 `my-font-file-bold.ttf`여도 글꼴 이름 "DejaVu Serif", 굵기 700으로 들어갑니다. 한글 이름이 들어 있는 글꼴은 목록에 한글 이름도 함께 보입니다.
  - **같은 글꼴의 굵기별 파일**(Pretendard-Regular, Pretendard-Bold…)은 한 글꼴로 묶입니다. 굵게(B)를 누르면 넣은 굵은 파일로 그립니다(예전에는 따로 된 글꼴이 되어 굵게가 가짜 굵게였음).
  - WOFF2는 압축을 풀 수 없어 **파일 이름으로 짐작**합니다(`-Bold`, `-SemiBoldItalic`, `-600` 등을 떼어 굵기·기울임으로).
  - .ttc(글꼴 모음)는 첫 글꼴을 씁니다.
- **글꼴 칸이 펼침 목록이 되었습니다**(▼ 또는 칸에 글자 입력). 맨 위 "넣은 글꼴(프로젝트에 포함)", 다음 "기본 글꼴", 불러온 경우 "시스템 글꼴(이 컴퓨터에만 있음)". 글꼴 이름은 그 글꼴로 그려 미리 보입니다.
  - 예전 칸(입력칸 + 브라우저 자동 완성)은 칸에 지금 글꼴 이름이 들어 있으면 그 이름과 맞는 것만 보여 줘서, 넣은 글꼴이 목록에 안 보이는 일이 있었습니다.
  - 칸에 치면 걸러지고(이름 일부), ↑↓ + Enter로 고릅니다. 목록에 없는 이름을 치고 Enter를 누르면 그 이름 그대로 적용합니다. Esc는 목록만 닫습니다.
  - 목록을 눌러도 글상자 편집·고른 글자 범위가 그대로 남습니다.
  - 목록 아래 "글꼴 파일 넣기…", "시스템 글꼴 불러오기". 넣은 글꼴에 마우스를 올리면 ×(프로젝트에서 빼기, 확인 후. 되돌리기 대상 아님).
- **넣자마자 적용:** 한 글꼴(굵기 여러 파일이어도)을 넣을 때 글상자를 골라 두었거나 편집 중 글자를 골라 두었으면 바로 적용합니다(되돌리기 한 번으로 취소). 아니면 상태 줄에 "목록 맨 위에서 고르십시오"라고 알립니다.
- **글꼴 파일을 캔버스에 끌어다 놓아도** 넣습니다.
- **한글 대체 글꼴:** 글꼴을 적용하면 꾸밈 값이 `"고른 글꼴", "Noto Sans KR", "Noto Sans CJK KR", "Malgun Gothic", sans-serif`가 됩니다. 영문 전용 글꼴을 골라도 한글이 브라우저 기본 글꼴(Windows에서는 명조체인 경우가 많음)로 나오지 않습니다.
- **`sans-serif`·`serif`·`monospace`를 골라도 적용되지 않던 것** 고침: 예전에는 따옴표를 붙여 넣어(`"serif"`) "serif라는 이름의 글꼴"을 찾았습니다(없으니 기본 글꼴).
- 같은 글꼴(이름·굵기·기울임 같음)을 다시 넣으면 건너뛰고 알립니다. 깨진 파일은 확인 창으로 알립니다.
- 예전 프로젝트: 파일 이름으로 등록된 글꼴(`texgyrecursor-regular` 등)은 그 이름 그대로 열리고 그대로 보입니다.

### 남이 준 파일 속 HTML 조각 막기
- 프로젝트·템플릿 파일이나 다른 웹페이지에서 복사한 요소 안에 HTML 조각을 숨겨 두면, 웹판에서 그 조각이 화면 HTML에 그대로 들어가 스크립트가 실행될 수 있었습니다(스와치 창을 열 때 실제로 확인).
- 고친 것:
  - 열 때 id는 영문·숫자·`_-`만(아니면 새 id), 스와치는 색 값만 받기
  - 붙여넣은 요소도 파일에서 읽은 것과 같은 정리를 거치기
  - 화면 HTML에 값을 넣는 곳(스와치·장 목록·레이어·템플릿 목록·영역 경로·이미지 주소)을 모두 특수문자 바꾸기
  - **웹판 배포 폴더에 `_headers` 추가**(`npm run build:web`이 만듦): Electron과 같은 허용 자원 목록(CSP)을 Cloudflare Pages 응답에 붙여, HTML 조각이 들어가도 스크립트로 실행되지 않습니다. 규칙은 `electron/csp.js` 한 곳에 있습니다.

### 저장
- **저장 실패를 알립니다.** 예전에는 상태 줄이 "저장하는 중…"에서 멈추고 아무 알림이 없었습니다. 이제 확인 창과 상태 줄에 까닭을 쉬운 말로 적습니다(다른 프로그램이 파일을 열어 둠·공간 부족·권한 없음·폴더 없음). 작업 내용과 "저장 안 됨" 표시는 그대로입니다.
- **저장을 두 번 눌러도 한 번만** 합니다(저장 중이면 그 저장을 기다림).
- **저장하는 동안 바꾼 내용**은 "저장 안 됨"으로 남깁니다(예전에는 저장된 것으로 표시되어 닫을 때 묻지 않고 사라질 수 있었음).
- 자동 저장과 파일 저장이 겹쳐도, 저장한 뒤에 쓸데없는 복구본이 남지 않습니다.
- 파일 명령(새로 만들기·열기 등)이 실패해도 조용히 멈추지 않고 알립니다.

### 탭(창) 여러 개와 자동 저장
- 예전에는 자동 저장 자리가 하나라, 웹판에서 탭을 두 개 열면 서로 덮어썼고 두 번째 탭이 첫 번째 탭의 **작업 중인** 내용으로 복구를 묻다가 "버리기"를 누르면 그 복구본과 이미지가 지워졌습니다.
- 이제 탭마다 자기 자리에 씁니다. 열려 있는 탭은 잠금(Web Locks)을 쥐고 있어서, 시작할 때는 **주인이 없는 자리**(비정상 종료·저장하지 않고 닫은 탭)만 복구를 묻습니다. 여러 개면 최근 것부터 하나씩 묻습니다.
- 복구 확인 창에 원래 파일 이름을 보입니다. 복구한 뒤 저장하면 새 파일 이름을 묻습니다(이전 실행의 파일 연결은 남지 않음).
- 이미지 원본은 탭들이 같이 씁니다. 한 자리를 지울 때 다른 자리가 쓰는 이미지는 남깁니다.
- 예전 버전이 남긴 복구본(자리 하나)도 그대로 복구를 묻습니다.

### 고친 것 — 속도

- **글 입력**: 문단 배치 결과를 기억해 두고(바뀐 문단만 다시 배치, 아래 문단은 위치만 옮김), 줄 DOM도 바뀐 줄만 바꿈. 문서 JSON은 안 바뀐 문단을 재사용. 커서만 움직일 때는 배치를 건너뜀
- **여러 장에 흐르는 글**: 지금 보이지 않는 장의 글상자는 그 장을 열 때 그림
- **강제 레이아웃 없애기**: 화면 좌표 계산마다 `getBoundingClientRect`를 부르던 것을 캐시(창 크기 바뀔 때만 다시 읽음). 눈금자는 모양이 같으면 다시 그리지 않음. 오버레이·레이어·장 목록·속성 패널·도구 막대는 바뀐 것만 DOM에 씀
- **끄는 동안**: 속성 패널 구조를 다시 만들지 않고 끝나면 한 번. 자동 저장은 조용할 때(`requestIdleCallback`)
- **장 전환**: 장 목록은 표시만 바꾸고, 장 속성 패널은 다시 만들지 않고 값만 채움
- **외곽선 글상자 크기 바꾸기**: 외곽선 이미지를 매번 새로 만들어 다시 디코딩하던 것을 하나로 재사용(11.5–12.3 → 8.4–9.7ms)
- 이미지 `decoding=async`, 패널 영역 `contain: strict`(캔버스에는 쓰지 않음: 출력과 화면이 1px 어긋나는 원인이 됨)

## 출력에서 알아 둘 점 (4단계)

- **고해상도 글자:** 배율 2 이상 출력은 1배 배치를 확대해 그립니다. Chrome은 "확대해 그린 글자"와 "기기 배율 2로 직접 그린 글자"를 **화면에서도** 다르게 그립니다(화면끼리 비교해도 최대 차이 221). 출력물은 확대해 그린 화면과 일치합니다. 차이는 한글 가로획의 가장자리 처리이고 위치는 같습니다.
- **벡터 PDF는 뷰어마다 고급 효과가 다르게 보입니다.** 같은 PDF를 두 뷰어로 확인했습니다:
  - poppler(리눅스 기본 뷰어 계열): 그라디언트 글자 주변에 옅은 사각형 선이 보임
  - pdf.js(Firefox 내장 뷰어): 외곽선 글자의 테두리가 사라지고 채움색 덩어리로 보임
  - Chrome 내장 뷰어(PDFium)와 Acrobat은 이 환경에서 확인하지 못했습니다.
  일반 글자·색·밑줄·형광펜·이미지는 두 뷰어 모두 정상입니다. 외곽선·그라디언트·그림자 같은 효과를 쓴 작업물은 래스터 PDF(기본값)가 안전합니다. 벡터 모드에서 효과가 있는 글자만 이미지로 바꿔 넣는 방식으로 보완할 수 있습니다.
- **래스터 PDF의 JPG 모드**는 이 시험 이미지(단색 위주)에서는 PNG보다 오히려 컸습니다(52만 대 48만 바이트). 사진이 많은 장에서만 이득이고, 사진이 든 장으로는 측정하지 않았습니다.
- **벡터 PDF 쪽 크기:** Chrome 인쇄가 쪽 크기를 미세하게 조정합니다(300×500px → 224.88×375.12pt, 정확히는 225×375pt).
- **큰 한글 업로드 글꼴:** 글자 범위 조각이 없는 글꼴은 파일 전체를 출력할 때마다 넣습니다. 수 MB짜리 한글 글꼴로 속도를 측정하지 않았습니다.

## 실제 환경에서 확인이 필요한 항목 (4단계)

1. 구글 폰트처럼 다른 출처의 웹 글꼴 넣기(`<link crossorigin>` 경로). 이 환경에서는 구글 폰트에 접근할 수 없어 같은 출처 스타일시트로만 확인했습니다.

3. 실제 폴더 선택 창(File System Access API). 테스트는 메모리 폴더로 대체해 파일 이름과 쓰기 순서만 확인했습니다.
